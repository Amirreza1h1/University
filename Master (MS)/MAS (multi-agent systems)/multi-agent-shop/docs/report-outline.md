# ساختار پیشنهادی گزارش پروژه فروشگاه چندعاملی

این فایل یک ساختار فارسی‌محور برای گزارش نهایی است. نام کلاس‌ها، فناوری‌ها و اصطلاحات استاندارد مانند `JADE`, `ACLMessage`, `Maven` و `PurchaseService` می‌توانند به انگلیسی نوشته شوند.

## ۱. صفحه عنوان

- نام دانشگاه و دانشکده
- نام درس: سیستم‌های چندعاملی (Multi-Agent Systems)
- عنوان پروژه: طراحی و پیاده‌سازی فروشگاه چندعاملی با JADE
- نام دانشجو، نام استاد و تاریخ

## ۲. هدف پروژه

- توضیح کوتاه درباره شبیه‌سازی خرید محصول با عامل فروشنده و عامل‌های خریدار
- هدف آموزشی: شناخت Agent، Behaviour و تبادل پیام ACL

## ۳. تعریف مسئله

- موجودی اولیه دو واحد A و دو واحد B
- یک فروشنده و چهار خریدار
- ثبت خرید موفق، رد خریدار `3B` برای محصول B و مدیریت اتمام موجودی

## ۴. نیازمندی‌ها

- فهرست قوانین عملکردی پروژه
- محدودیت نام عامل‌ها و تعداد درخواست‌ها
- تنظیمات میزبان `127.0.0.1` و درگاه `7778`
- نیازمندی‌های کیفیت: سادگی، تست‌پذیری و جداسازی منطق تجاری

## ۵. ابزارها و فناوری‌ها

- Java 17
- Apache Maven
- JADE 4.6.0
- JUnit 5
- Visual Studio Code و Microsoft Extension Pack for Java

## ۶. معرفی JADE

- تعریف کوتاه JADE و نقش آن در ساخت Multi-Agent System
- مفهوم Main Container، Agent، Behaviour، AMS، RMA و Sniffer
- تفاوت عامل‌های کاربردی پروژه با عامل‌های مدیریتی JADE

## ۷. معماری سیستم

- معرفی لایه راه‌اندازی، Agentها، Behaviourها، مدل و Service
- استفاده از نمودارهای فایل `architecture.md`
- توضیح مالکیت یکتای موجودی توسط فروشنده

## ۸. تعریف عامل‌ها

- `SellerAgent`: مسئول موجودی، شمارش درخواست‌ها و گزارش نهایی
- `BuyerAgent`: مسئول یک درخواست و فهرست خرید شخصی
- مشخصات عامل‌های `seller`, `1B`, `2B`, `3B`, `4B`

## ۹. پروتکل ارتباط پیام‌ها

- `ACLMessage.REQUEST`, `INFORM`, `REFUSE`, `FAILURE`
- Ontology برابر `multi-agent-shop`
- FIPA Request protocol برابر `fipa-request`
- استفاده از `conversation-id`, `reply-with` و `in-reply-to`
- نقش `MessageTemplate` در فیلتر کردن پیام‌ها

## ۱۰. جزئیات مهم پیاده‌سازی

- راه‌اندازی برنامه‌نویسی‌شده JADE در `Main`
- استفاده از `block()` برای جلوگیری از Busy Waiting
- ساخت پاسخ با `request.createReply()`
- مدیریت ورودی نامعتبر بدون توقف فروشنده
- چاپ گزارش نهایی فقط یک‌بار

## ۱۱. قوانین تجاری

- موجودی اولیه و کاهش فقط پس از موفقیت
- بررسی محدودیت `3B` قبل از بررسی موجودی
- ثبت فقط خریداران موفق
- جلوگیری از منفی شدن موجودی
- استقلال `PurchaseService` از JADE

## ۱۲. موارد آزمون

- معرفی ۲۰ آزمون JUnit شامل ۱۳ آزمون منطق خرید و ۷ آزمون پیکربندی سناریوها
- جدول سناریوهای فایل `test-scenarios.md`
- نتیجه مورد انتظار و واقعی هر دسته آزمون

## ۱۳. نتایج اجرا

- فرمان‌های Build، Test و Run
- نتایج چهار خریدار
- موجودی نهایی `{A=2, B=0}`
- خریداران موفق `[1B, 2B]`
- تعداد درخواست‌های پردازش‌شده برابر ۴
